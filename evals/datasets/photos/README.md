# Фото-референсы для evals

`v1.jsonl` — 30 случаев «хочу вот так» по каталогу фейкового салона (`adapters/crm/fake.py`):
что должно быть на фото (`shows`), какая услуга ожидается (`expected_service_id`) и эталонное
описание (`reference`) — каким должен быть ответ модели зрения.

Самих снимков в репозитории нет: репозиторий публичный, а у фото есть авторы и могут быть лица.

## Как собрать снимки

1. Источник — работы мастеров салона-пилота с их письменного согласия или фото со свободной
   лицензией (CC0, собственные снимки). Не брать фото из переписки с клиентами и из чужих
   соцсетей без разрешения.
2. В кадре — результат услуги (ногти, брови, ресницы, волосы). Без лиц целиком, без документов
   и без текста с персональными данными.
3. Назвать файлы как в манифесте (`photo-001.jpg` … `photo-030.jpg`), JPEG, PNG или WebP до 10 МБ.
4. Хранить вне репозитория, например `D:/private-evals/photos`.

## Как прогнать

```bash
poetry run python -m evals.photo_run --photos-dir D:/private-evals/photos
```

Нужен ключ модели зрения (`LLM_CLOUDRU_API_KEY` или `LLM_VISION_BASE_URL` + `LLM_VISION_API_KEY`).
Отчёт — `evals/reports/<дата>-photos-v1.md`: точность первой услуги среди фото, на которые агент
ответил бы сам, доля таких фото и рекомендация.

Режим салона `photo_mode=guess` включают, только если точность не ниже 80% на 10+ ответах
(`docs/adr/012-photo-references.md`). Без этого фото уходят администратору (`photo_mode=admin`).

`--offline` подставляет эталонные описания вместо модели: проверяет подбор услуги по каталогу
без сети и без снимков (так он работает в CI).
