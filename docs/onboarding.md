# Подключение пилотного салона

Подключение — одна команда по анкете салона:

```bash
poetry run python -m scripts.onboard_salon scripts/onboarding.example.toml
```

Скрипт создаёт салон и импортирует каталог из YCLIENTS, включает теневой режим, выдаёт одноразовый
код привязки админ-бота, подключает каналы и ставит вебхуки, загружает ответы анкеты в базу знаний
как FAQ и в конце прогоняет smoke-проверку: тестовое сообщение из каждого канала доходит до агента
и даёт черновик. Тестовый клиент после проверки удаляется.

Токены каналов в файле анкеты не хранятся: в нём только имена переменных окружения
(`token_env = "LAVANDA_TELEGRAM_TOKEN"`). Перед запуском задайте их в окружении сервера.

## Чек-лист для салона

До запуска салон готовит:

- [ ] **Договор поручения** на обработку персональных данных клиентов (ч. 3 ст. 6 152-ФЗ):
      салон — оператор, сервис — обработчик. Без подписанного договора пилот не запускаем.
- [ ] **Реквизиты оператора** для страницы политики `/privacy/<slug>`: название (ИП или ООО),
      ИНН, адрес, e-mail для обращений. Текст политики сверяет юрист салона.
- [ ] **YCLIENTS**: ID филиала и включённая онлайн-запись; партнёрский токен сервиса добавлен
      в интеграции филиала.
- [ ] **Telegram Business**: аккаунт салона с Telegram Premium — без Premium режим Business недоступен.
      Владелец подключает бота в «Настройки → Telegram для бизнеса → Чат-боты» и даёт права
      отвечать на сообщения. Без Premium — обычный бот салона (`business = false`).
- [ ] **ВКонтакте**: права администратора сообщества; ключ доступа сообщества с правом «Сообщения
      сообщества»; включены сообщения сообщества. После онбординга в «Управление → Работа с API →
      Callback API» указать адрес и секретный ключ из вывода скрипта, событие «Входящее сообщение».
- [ ] **MAX**: заявка на бота в кабинете business.max.ru одобрена, токен бота получен.
      Пока заявка не одобрена, MAX подключается позже — остальные каналы это не задерживает.
- [ ] **Анкета онбординга**: частые вопросы, которых нет на сайте и в CRM (парковка, оплата,
      правила отмены, подготовка к процедурам) — раздел `[[faq]]` файла анкеты.
- [ ] **Администраторы**: владелец открывает ссылку привязки из вывода скрипта
      (`https://t.me/<админ-бот>?start=<код>`). Код одноразовый и действует 7 дней;
      для каждого администратора — свой код (повторный запуск скрипта выдаёт новый).

## Теневой режим

Пилот начинается в теневом режиме: агент не отвечает клиенту сам, а присылает администратору
в админ-бот вопрос клиента и черновик ответа с кнопками:

- **Отправить** — черновик уходит клиенту в тот мессенджер, из которого он написал;
- **Исправить** — бот просит прислать исправленный текст, и клиенту уходит он;
- **Отвечу сам** — черновик не пригодился, администратор отвечает клиенту сам.

Команда `/report` показывает точность за неделю: долю черновиков, отправленных без правок или с малыми
правками. Салон переводится на автопилот (`reply_mode = "autopilot"`), когда за неделю не меньше 90%
черновиков ушли без правок на 100+ диалогах и не было критических ошибок (неверная цена или время).

Виджет на сайте салона в теневом режиме не подключают: клиент на сайте ждёт ответ сразу.

## Согласие на обработку данных

При первом обращении клиент получает короткий текст со ссылкой на `/privacy/<slug>`. Пока клиент
не ответил «Согласен» или «Согласна», агент отвечает только на общие вопросы: телефон и e-mail
вырезаются из сообщений до сохранения и до отправки в LLM, записать нельзя. Команда `/forget`
или просьба «удалите мои данные» отзывает согласие: переписка удаляется, карточка клиента обезличивается.
Переписка старше `retention_days` (по умолчанию 365 дней) удаляется ночной задачей.

## Настройки салона после пилота

- `reminders_enabled = true` — напоминания за 24 и 2 часа в мессенджер клиента. Включать, только
  если салон не шлёт SMS-напоминания из YCLIENTS: дублировать нельзя.
- `average_check_rub` — средний чек для еженедельного отчёта в рублях; без него берётся средняя
  цена записей салона за 90 дней.
- `work_start`, `work_end` — рабочее время администраторов: ответы вне его — отдельная строка отчёта.
- Токен сотрудника YCLIENTS — для записи от имени салона без SMS-кода, переноса и отмены записей.
- Вебхук YCLIENTS об изменении записей: адрес `/api/v1/webhooks/yclients/<salon_id>/<секрет>`
  (секрет выводится из `SECURITY_WEBHOOK_KEY`), чтобы переносы и отмены из YCLIENTS были видны сразу.

## После запуска

- Сообщения о передаче диалога приходят в админ-бот с кнопкой «Вернуть агенту»; ответ на такое
  уведомление уходит клиенту.
- `/token` в админ-боте выдаёт JWT для API инбокса (`/api/v1/admin/conversations`) на 8 часов.
- Сайт салона изменился — `POST /api/v1/salons/{id}/reindex` с тем же токеном: ответ 202 и адрес
  `GET /api/v1/jobs/{id}` с прогрессом. Сайт берётся из настройки салона `site_url`.
- Фото «хочу вот так» по умолчанию уходят администратору (`photo_mode=admin`). Подбор услуги
  по фото (`photo_mode=guess`) включают после замера точности на 30 фото-референсах
  (`evals/datasets/photos/README.md`, нужно не меньше 80%).
- Поиск по истории: `GET /api/v1/admin/search?q=наращивание&date_from=2026-09-01&date_to=2026-09-30` —
  сообщения клиентов с согласием на обработку ПДн, ближайшие по смыслу.
- Голосовые и файлы клиент получает вежливый ответ, администратор — уведомление.
