# Архитектура beauty-agent

Модульный монолит на FastAPI (ADR 001): один сервис с чёткими модулями, PostgreSQL и Redis,
воркеры Celery на RabbitMQ (ADR 002, 003). Код делится на слои: адаптеры внешних систем → домен →
агент → сервис диалога → API и воркеры.

```mermaid

    client([Клиент: сайт, Telegram, VK, MAX]) --> api
    admin([Администратор салона]) <--> adminbot

    subgraph app [beauty-agent]
        api[API, веб-чат и вебхуки<br/>api/] -->|склейка, очередь| worker[Воркер Celery<br/>workers/]
        api --> conv
        worker --> conv[Сервис диалога<br/>conversation/]
        conv -->|теневой режим| adminbot[Админ-бот<br/>adapters/channels/admin_bot.py]
        conv -->|outbox| channels[Каналы<br/>adapters/channels/]
        conv --> agent[Цикл агента<br/>agent/loop.py]
        agent --> guard[Guardrails<br/>вход и выход]
        agent --> tools[9 инструментов<br/>agent/tools.py]
        tools --> engine[Движок записи<br/>domain/booking_engine]
        tools --> rag[RAG: гибридный поиск<br/>rag/]
        tools --> catalog[Каталог<br/>catalog/]
```

## Путь сообщения клиента

1. **Вход.** Веб-чат (`api/widget_ws.py`): Origin салона, лимиты на сессию и IP, одно сообщение за раз.
   Мессенджеры (`api/v1/webhooks.py`): секрет вебхука до запроса в БД, отсев повтора (SET NX), склейка
   пачки сообщений за 2,5 секунды, задача Celery; ответ мессенджеру сразу (ADR 002).
2. **Сервис диалога** (`conversation/service.py`): клиент по «канал + ID», диалог, блокировка в Redis,
   защита от повторного вебхука, дневной бюджет салона на LLM. Согласие по 152-ФЗ (`domain/consent.py`):
   без него телефон и e-mail вырезаются до сохранения и до LLM, запись недоступна. Диалог у администратора —
   агент молчит, сообщения клиента пересылаются в админ-бот (`conversation/handoff.py`).
3. **Входные guardrails** (`agent/guardrails.py`): длина, prompt injection, здоровье, жалобы
   и скидки — без вызова модели, сразу ответ или администратор.
4. **Контекст** (`agent/context.py`): промпт v1, профиль клиента, резюме, данные инструментов,
   последние 4 реплики — в пределах 3 500 токенов.
5. **Цикл** (`agent/loop.py`): LLM → инструменты → LLM, не больше 6 шагов. Аргументы проверяет
   Pydantic; кривой JSON — одна попытка исправиться; дальше — администратор.
6. **Инструменты**: цены и мастера — из каталога в БД; время — из CRM через движок записи (2–3 варианта
   под номерами в Redis); запись — по номеру варианта, ровно один раз (ключ идемпотентности, перепроверка
   слота, ограничение исключения в БД); сведения о салоне — гибридный поиск по сайту.
7. **Выходные guardrails**: иероглифы — перегенерация; цены и время, которых нет в данных инструментов, —
   безопасный ответ вместо выдумки.
8. **Сохранение**: сообщения с токенами и стоимостью, журнал вызовов инструментов, резюме; состояние
   диалога в Redis на 24 часа с восстановлением из PostgreSQL.
9. **Ответ.** Мессенджер — строка outbox в той же транзакции, отправка воркером ровно один раз.
   Неотправленное (сбой мессенджера) досылает периодическая задача.
   Теневой режим пилота (`conversation/shadow_mode.py`) — черновик в админ-бот с кнопками «Отправить»,
   «Исправить», «Отвечу сам»; отчёт точности решает, когда переводить салон на автопилот.

## Фоновые задачи (Celery beat)

| Задача | Когда | Что делает |
| --- | --- | --- |
| `periodic.reminders` | каждые 5 минут | напоминания за 24 и 2 часа; перед отправкой сверка записи с CRM |
| `periodic.outbox_sweep` | каждую минуту | досылка исходящих, которые не ушли с первого раза |
| `periodic.catalog_sync` | 04:00 | цены и услуги из YCLIENTS — агент не называет устаревшую цену |
| `periodic.retention` | 03:30 | удаление переписки старше срока хранения салона |
| `periodic.weekly_report` | понедельник 10:00 | отчёт салону в админ-бот: записи ИИ в рублях, ответы вне рабочего времени, расход на LLM |
| `periodic.embed_messages` | каждую минуту | векторы новых сообщений клиентов с согласием — для поиска по истории |

Задачи по запросу (очередь periodic, статус и прогресс — `core/jobs.py`, `GET /api/v1/jobs/{id}`):

| Задача | Кто ставит | Что делает |
| --- | --- | --- |
| `jobs.reindex` | `POST /api/v1/salons/{id}/reindex`, `scripts/make_demo.py` | обход сайта салона с прогрессом «N из M страниц»; повтор продолжает с упавшей страницы |

Счёт по тарифу «Результат» (59 ₽ за запись ИИ) — по правилу `domain/billing.py`, тому же, что в договоре;
выгрузка за месяц — `scripts/billing_export.py`.

## Принципы

- **Факты даёт код, модель только разговаривает** (ADR 006): цена, время и запись не зависят от модели.
- **Изоляция салонов** (ADR 008): `salon_id` в каждом запросе подставляет репозиторий; поиск по знаниям — тоже.
- **Хотя бы один раз + идемпотентность**: повтор вебхука, задачи или нажатия кнопки не даёт второго ответа.
- **152-ФЗ**: данные и модели в РФ, телефоны и e-mail маскируются в логах, Sentry и трассах,
  бэкапы шифруются, согласия хранятся с версией документа, отзыв удаляет переписку, ночная задача
  удаляет диалоги старше срока хранения; токены каналов в БД зашифрованы (Fernet).
- **Деградация, а не падение**: CRM недоступна — заявка администратору; модель недоступна — резервная,
  затем администратор; сайт салона недоступен — знания из карточки филиала.

## Качество

- Тесты: юнит, интеграционные на PostgreSQL и Redis в контейнерах, контрактные для YCLIENTS, e2e диалога.
- Evals (`evals/`): 100 сценариев записи и 30 провокаций; инварианты — ровно 100%, качество — с допуском;
  гейт в CI на каждый PR, затрагивающий агента. RAG — recall@5 на 30 вопросах.
