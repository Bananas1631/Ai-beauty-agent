# ADR 005. Свой цикл агента вместо LangChain или LangGraph

- Статус: принято
- Дата: 2026-10-31

## Контекст

Агенту нужно: function calling у трёх провайдеров с разными форматами (OpenAI-совместимый
Qwen и YandexGPT, `functions` у GigaChat), лимит шагов, проверка аргументов, guardrails до и после
модели, журнал вызовов и точный учёт токенов и рублей. Сценарий один — запись в салон.

## Варианты

1. **LangChain / LangGraph.** Готовые абстракции агента, памяти, инструментов и графов.
   Слой поверх слоя: сложно отлаживать, где именно потерялся аргумент; частые несовместимые
   версии; GigaChat и YandexGPT поддержаны сторонними пакетами с задержкой.
2. **Свой цикл (~200 строк, `agent/loop.py`).** «LLM → инструменты → LLM», не больше 6 шагов,
   Pydantic для аргументов, единый интерфейс `LLMClient` для провайдеров.

## Решение

Свой цикл. Логика короткая и полностью покрыта тестами на фейковом LLM (`ScriptedLLM`):
повтор при невалидном JSON, эскалация на 7-м шаге, замена выдуманной цены.

## Последствия

- Каждый шаг виден в журнале `tool_calls` и в трассе — без «магии» фреймворка.
- Ветвящиеся сценарии (перенос, отмена, лист ожидания) добавляются инструментами, а не графом.
- Пересмотреть, если появится несколько агентов с передачей задач между ними или
  долгоживущие процессы с ожиданием событий (это скорее Temporal, см. блок 11).
- Проверено измерением в декабре: тот же агент на LangGraph даёт ту же точность и стоимость,
  но +22 мс на сообщение и 16 зависимостей — [ADR 010](010-langgraph-experiment.md).
