# ADR 007. Выбор основной и резервной модели

- Статус: предложено — ждёт прогона evals на живых моделях
- Дата: 2026-10-31

## Контекст

Кандидаты — модели, которые можно использовать без передачи диалогов за рубеж (152-ФЗ):
Qwen3-235B в Cloud.ru, GigaChat 2 Lite / Max, YandexGPT Lite / Pro.
Критерии в порядке важности: доля сценариев, доведённых до верной записи; точность вызова
инструментов; стоимость диалога; p95 задержки.

## Правило решения

- Основная модель фиксируется, если доводит до верной записи **не меньше 85%** сценариев
  `evals/datasets/booking/v1`.
- Если ни одна не дотягивает — маршрутизация: дешёвая модель для простых вопросов, сильная для записи.
- Резервная — лучшая по точности среди моделей другого провайдера: отказ провайдера не должен
  отключать обе модели сразу.

## Что есть сейчас

Прогон на живых моделях не выполнен: ключей GigaChat API, Yandex Cloud и Cloud.ru ещё нет.
Есть нижняя планка — офлайн-модель на правилах (`evals/reports/2026-10-15-booking-v1.md`):
90% сценариев, 81% верных записей, 100% верных передач администратору. Живая модель
обязана быть заметно лучше: она понимает «к Марине» и «в субботу», а правила — нет.

Порядок по умолчанию до прогона: `LLM_DEFAULT_MODELS=["qwen3-235b", "gigachat-2-lite"]`.

## Как закрыть решение

```bash
make evals MODELS=qwen3-235b,gigachat-2-lite,yandexgpt-lite
```

Перед прогоном проверить, поддерживает ли YandexGPT Lite вызов инструментов в OpenAI-совместимом
режиме; если нет — сравнивать YandexGPT Pro. Результаты внести в этот ADR и сменить статус на «принято».
