# Интеграция с мессенджером MAX

Адаптер: `src/beauty_agent/adapters/channels/max.py`. Сервис диалога и агент про MAX не знают:
обновление превращается в общий `ChannelUpdate`, ответ уходит через тот же outbox.

Сверено с документацией dev.max.ru 16 октября 2026 года.

## Bot API

| Что | Как |
| --- | --- |
| Адрес API | `https://platform-api2.max.ru` (`MAX_API_URL`) |
| Токен | заголовок `Authorization: <token>`; токен в адресе запроса больше не поддерживается |
| Проверка токена | `GET /me` → `user_id`, `name`, `username` |
| Отправка | `POST /messages?chat_id=<id>`, тело `{"text": "...", "notify": true}`, текст до 4000 символов |
| Вебхук | `POST /subscriptions`, тело `{"url", "update_types", "secret"}` |
| Лимит | до 30 запросов в секунду к API |

Ответы 429 и 5xx — временный сбой, отправку повторит задача Celery; 4xx — окончательный отказ
(бот удалён из чата, токен отозван), строка outbox получает статус `failed`.

## Вебхук

- Только HTTPS на порту 443 с сертификатом доверенного центра или Минцифры; самоподписанные не принимаются.
- Секрет (`secret`, 5–256 символов `A-Z a-z 0-9 _ -`) MAX присылает в заголовке `X-Max-Bot-Api-Secret`.
  Секрет выводится из `SECURITY_WEBHOOK_KEY` и ID канала (HMAC-SHA256) и в БД не хранится.
- MAX ждёт ответ 200 за 30 секунд; иначе до 10 повторов с растущей паузой (60, 150, 375 с…),
  а через 8 часов без успеха отписывает бота. Поэтому вебхук отвечает 200 сразу, а обработка — в очереди.
- Повтор вебхука отсекается по ID сообщения (`message.body.mid`): у MAX нет отдельного ID обновления.
- Обновления: `message_created` (сообщение) и `bot_started` (клиент открыл бота — первое касание).
  Принимаются только личные диалоги (`recipient.chat_type = dialog`).

## Сертификат Минцифры

Сервер API работает на сертификате российского удостоверяющего центра, которого нет в наборе
корневых сертификатов Python (certifi). Проверку TLS не отключаем — добавляем корневой сертификат:

1. Скачать «Russian Trusted Root CA» с портала Госуслуг (gosuslugi.ru/crt) и сверить отпечаток.
2. Положить файл на сервер в `/opt/beauty-agent/certs/russian_trusted_root_ca.pem`
   (docker-compose.prod монтирует папку `certs` в контейнеры только для чтения).
3. Задать `MAX_CA_BUNDLE=/certs/russian_trusted_root_ca.pem`.

Клиент MAX доверяет и публичным корневым сертификатам, и этому; остальные адаптеры — только публичным.

## Что сверить при подключении

- Структура `Update` для `message_created` и `bot_started` на страницах объектов документации
  не раскрыта полностью: разбор написан по примерам Bot API и защищён от отсутствующих полей.
  На первом реальном боте сохранить пример обновления в `tests/fixtures/max/` и сверить с тестами.
- Заявка на бота в business.max.ru рассматривается несколько дней — подавать до запуска пилота.
