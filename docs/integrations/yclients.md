# YCLIENTS API: шпаргалка для агента

Источник — официальная документация REST API YCLIENTS (раздел «Онлайн-запись»).
Живые запросы ещё не делались: партнёрского токена нет. Всё, что помечено **[сверить]**,
нужно подтвердить первым же запросом с токеном и поправить здесь и в фикстурах.

## Подключение

| Что | Значение |
|---|---|
| Адрес | `https://api.yclients.com/api/v1/` (зеркало `api.yclients.ru`) |
| Формат | JSON, `Content-Type: application/json` |
| Версия API | заголовок `Accept: application/vnd.yclients.v2+json` |
| Авторизация | `Authorization: Bearer <partner_token>` или `Bearer <partner_token>, User <user_token>` |

- **Партнёрский токен** выдаётся разработчику в маркетплейсе YCLIENTS. Его хватает для публичных
  методов онлайн-записи — тех же, что вызывает виджет записи на сайте салона.
  Утечка — злоумышленник от нашего имени создаёт записи во всех подключённых филиалах: токен
  отзывается в кабинете разработчика, новый кладётся в `.env` на сервере.
- **Пользовательский токен** — доступ сотрудника конкретного салона (`POST /auth`).
  Нужен только для закрытых методов: список записей, клиенты. Хранится зашифрованным
  у салона, в `.env` — только для разработки. Утечка — доступ к клиентской базе салона (ПДн, 152-ФЗ).

## Конверт ответа

```json
{"success": true, "data": {...}, "meta": {...}}
{"success": false, "data": null, "meta": {"message": "Текст ошибки"}}
```

Ошибка может прийти и с HTTP 200, и с 4xx — адаптер смотрит и на код, и на `success`.

## Методы по сценариям агента

| Сценарий | Метод | Повторять при сбое? |
|---|---|---|
| Данные филиала: адрес, часы, часовой пояс | `GET company/{company_id}` | да |
| Каталог услуг с ценами и длительностью | `GET book_services/{company_id}` | да |
| Мастера, которые делают услугу | `GET book_staff/{company_id}?service_ids[]={id}` | да |
| Дни, в которые есть свободное время | `GET book_dates/{company_id}?service_ids[]=&staff_id=&date_from=&date_to=` | да |
| Свободное время мастера на день | `GET book_times/{company_id}/{staff_id}/{YYYY-MM-DD}?service_ids[]=` | да |
| Проверить, что запись возможна | `POST book_check/{company_id}` | да: ничего не создаёт |
| Отправить клиенту SMS-код | `POST book_code/{company_id}` | **нет**: второе SMS |
| Создать запись | `POST book_record/{company_id}` | **нет никогда** |
| Найти запись после таймаута создания | `GET records/{company_id}?staff_id=&start_date=&end_date=` (нужен user-токен) | да |

### Поля, которые берёт адаптер

- `company`: `id`, `title`, `public_title`, `timezone_name`, `address`, `phone`, `site`, `schedule`, `short_descr`.
- `book_services`: `data.services[]` — `id`, `title`, `category_id`, `price_min`, `price_max`,
  `seance_length` (секунды), `comment`, `active`; `data.category[]` — `id`, `title`.
- `book_staff`: `id`, `name`, `specialization`, `position.title`, `bookable`, `rating`.
- `book_dates`: `data.booking_dates[]` — даты `YYYY-MM-DD`, где есть свободные окна.
- `book_times`: `data[]` — `time` (`"10:00"`), `seance_length`, `datetime` (ISO 8601 со смещением).
- `book_record` (ответ): `data[]` — `id`, `record_id`, `record_hash`.

### Тело запроса на запись

```json
{
  "phone": "79161234567",
  "fullname": "Анна",
  "email": "",
  "comment": "Запись через ИИ-администратора",
  "api_id": "<ключ идемпотентности, до 64 символов>",
  "appointments": [
    {"id": 1, "services": [101], "staff_id": 11, "datetime": "2026-10-20T10:00:00+03:00"}
  ]
}
```

Если филиал требует подтверждение телефона, в теле нужен ещё `code` из SMS (`book_code`).
Тогда у агента появляется шаг «введите код из SMS» — адаптер сообщает об этом ошибкой
`ConfirmationRequiredError`. **[сверить]** — включено ли подтверждение у пилотных салонов.

## Свободное время

YCLIENTS сам отдаёт готовые старты (`book_times`) с учётом графика, перерывов и чужих записей.
Свой расчёт слотов (`domain/booking_engine/slots.py`) нужен для двух вещей:
фейкового CRM в тестах и отбора 2–3 удобных вариантов из длинного списка.

Слот однозначно задаётся тройкой «мастер + услуга + время начала»: ID слота у YCLIENTS нет.

## Лимиты

- Не больше **200 запросов в минуту** и **5 в секунду** с одного IP.
  Адаптер держит 5 rps ограничителем (token bucket); при нескольких процессах — общий счётчик в Redis.
- Поиск окон дорогой: `book_dates` + по одному `book_times` на каждого мастера и день.
  Поэтому ищем не дальше 3 дней с окнами и кэшируем слоты на 60 секунд.

## Ошибки → доменные исключения

| Ответ | Что значит | Исключение | Повтор |
|---|---|---|---|
| 401, 403 | токен неверный или отозван | `ProviderAuthError` | нет |
| 404 | филиал, мастер или запись не найдены | `NotFoundError` | нет |
| 422 + «занято»/«недоступно» или код 433–437 **[сверить]** | время заняли | `SlotTakenError` | нет, предложить другое |
| 422 + упоминание кода подтверждения | нужен SMS-код | `ConfirmationRequiredError` | нет |
| прочие 4xx | неверный запрос | `DomainValidationError` | нет |
| 429 | превышен лимит | `ProviderUnavailableError` | да, с паузой |
| 5xx, таймаут, обрыв соединения | YCLIENTS недоступен | `ProviderUnavailableError` | чтение — да; запись — нет |

## Что нельзя повторять автоматически

**Создание записи.** Если `book_record` упал по таймауту, запрос мог дойти, и запись уже есть.
Повтор создал бы вторую запись, и клиент получил бы два SMS. Поэтому после таймаута адаптер
сначала ищет запись клиента на это время (`records`, нужен user-токен); не нашёл или нет токена —
запись уходит в статус «администратор подтвердит». `api_id` = наш ключ идемпотентности: по нему
запись находится в CRM при разборе.

**SMS-код.** Повтор `book_code` отправит клиенту второе SMS и может упереться в лимит отправок.

## Фикстуры

`tests/contract/fixtures/yclients/*.json` — ответы в формате документации, с вымышленными
данными. Когда появится токен: сделать по одному запросу каждого метода на 1–2 публичных
филиалах, удалить из ответов ПДн (телефоны, имена клиентов, e-mail), заменить файлы и прогнать
контрактные тесты. Если тест упал — YCLIENTS отвечает не так, как написано в документации.
