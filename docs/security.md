# Безопасность

Что защищаем: переписку и телефоны клиентов салонов (персональные данные, 152-ФЗ), токены ботов
и сообществ салонов, доступ к записи в YCLIENTS и бюджет салона на LLM.

## Секреты и шифрование

| Что | Как хранится | Смена |
| --- | --- | --- |
| Токены ботов Telegram и MAX, токен и код подтверждения VK | в БД только зашифрованными: Fernet (AES-128-CBC + HMAC-SHA256), `core/security.py` | ключ — `SECURITY_FERNET_KEYS`; ротация без простоя через MultiFernet (ниже) |
| Секреты вебхуков каналов | не хранятся: HMAC-SHA256 от `SECURITY_WEBHOOK_KEY` и ID канала | смена ключа меняет все секреты — заново зарегистрировать вебхуки (`scripts/onboard_salon.py`) |
| JWT API инбокса | подпись HS256 ключом `SECURITY_JWT_SECRET` | смена разлогинивает всех; refresh-токены продолжают работать |
| Refresh-токены | в Redis только SHA-256 токена | отзыв — удаление цепочки |
| Ключи LLM, партнёрский токен YCLIENTS | только `.env` на сервере, в репозитории нет | — |

В проде сервис не стартует без `SECURITY_*` (dev-ключи разрешены только локально). В репозитории
pre-commit с gitleaks не даёт закоммитить секрет; `.env` в `.gitignore`.

**Смена ключа шифрования без потери токенов:**

1. Новый ключ: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`.
2. `SECURITY_FERNET_KEYS=<новый>,<старый>` и перезапуск: шифрует первый ключ, расшифровывают оба.
3. `poetry run python -m scripts.rotate_keys` — перешифровать учётные данные всех каналов новым ключом.
4. Убрать старый ключ и перезапустить. Тест `test_key_rotation_keeps_old_tokens` проверяет весь цикл.

## Доступ администраторов

- Вход — только через админ-бот: администратор привязывается к салону одноразовым кодом
  (128 бит, 7 дней, сгорает при первом использовании — `GETDEL`). Код для владельца выдаёт
  онбординг, для администраторов — владелец командой `/invite`.
- Роли: **владелец** (команда салона: `GET /api/v1/admin/team`, отключение администратора) и
  **администратор** (инбокс, черновики, отчёты). Роль в JWT — для клиента; сервер проверяет роль
  и активность по БД на каждый запрос, поэтому понижение и отключение действуют сразу.
- Access-токен — 15 минут. Refresh-токен — 30 дней, непрозрачный, одноразовый: `POST
  /api/v1/admin/token/refresh` выдаёт новую пару, старый токен сгорает. Повтор уже использованного
  refresh-токена означает, что его скопировали: отзывается вся цепочка этого входа.
- Проверка JWT: явный список алгоритмов (`HS256` — токен с `alg=none` не пройдёт), обязательные
  `exp`, `iat`, `sub`, `aud`, `iss`. Салон берётся из токена, а не из адреса запроса.
- Кнопки и ответы в админ-боте проверяют, что нажавший — активный администратор того салона,
  которому принадлежит черновик или диалог.

## Вебхуки

- Секрет проверяется первым, до запроса в БД, сравнение за постоянное время (`hmac.compare_digest`).
  Telegram — заголовок `X-Telegram-Bot-Api-Secret-Token`, MAX — `X-Max-Bot-Api-Secret`, VK — поле
  `secret`. YCLIENTS заголовков не умеет — секрет в адресе, в логах он маскируется.
- 20 неверных секретов с одного IP за 10 минут — дальше 429 даже с верным секретом: перебор бесполезен.
- Верный секрет — лимит 600 запросов в минуту на канал: сломанный или взломанный бот не забьёт очередь.
- Тело — не больше 256 КБ (и 1 МБ на уровне Caddy). Повтор обновления отсекается по ID (SET NX).
- Вебхуку YCLIENTS не доверяем по содержимому: из события берётся только ID записи, сама запись
  перечитывается через API.

## Лимиты частоты

Счётчики в Redis (общие для всех процессов), фиксированное окно, `INCR` и `EXPIRE` одним Lua-скриптом.

| Что | Лимит |
| --- | --- |
| Сообщения веб-чата | 15 в минуту на сессию, 60 на IP |
| Страницы салонов и публичный API | 120 в минуту на IP |
| Вебхук канала | 600 в минуту на канал; 20 неверных секретов за 10 минут на IP |
| API инбокса | 300 в минуту на администратора |
| Обновление токенов | 20 в минуту на IP |
| Расход на LLM | дневной лимит салона в рублях, затем — администратор |

IP клиента за Caddy берётся из `X-Forwarded-For`, которому uvicorn доверяет только внутри сети
Docker (`FORWARDED_ALLOW_IPS`).

## Браузер

- Строгая CSP на HTML-страницах: скрипты, стили и соединения только со своего домена,
  `frame-ancestors 'none'`, `object-src 'none'`; плюс `X-Content-Type-Options`, `Referrer-Policy`,
  HSTS в Caddy.
- WebSocket чата проверяет `Origin`: свой домен и `allowed_origins` из настроек салона (только
  `https://`). Чужой сайт не поговорит с агентом от имени посетителя (CSWSH).
- Виджет для сайтов салонов (`/widget.js`, 10 КБ) живёт в закрытом Shadow DOM: стили сайта
  его не ломают, а скрипты сайта не читают переписку. Текст ответов вставляется только через
  `textContent` — ответ модели не выполнится как HTML. В `localStorage` — только случайный ID сессии.

## Входные данные

- SQL — ORM или `text()` с именованными параметрами: значения не попадают в текст запроса.
- ID из диалога в адресе YCLIENTS — только цифры (`numeric_id`): значение не меняет путь запроса.
- Обход сайта салона для базы знаний — через безопасный клиент: запрет внутренних адресов (SSRF),
  проверка каждого редиректа, лимиты размера и времени.
- Сообщение клиента для агента — данные, а не инструкции: guardrails на prompt injection до модели,
  проверка цен и времени в ответе после модели (ADR 006).

## Персональные данные (152-ФЗ)

- Согласие с версией документа; без него телефон и e-mail вырезаются до БД и до LLM, записи нет.
- Отзыв согласия (`/forget`) удаляет переписку и журнал инструментов, обезличивает карточку.
- Ночная задача удаляет диалоги старше срока хранения салона.
- Телефоны и e-mail маскируются в логах, Sentry и трассах Langfuse; Sentry без тела запроса,
  cookies, заголовков авторизации и локальных переменных.
- Данные и модели — в РФ (Cloud.ru, Yandex Cloud, GigaChat); бэкапы шифруются.

## Инфраструктура

- Наружу открыты только 80/443 (Caddy с Let's Encrypt); PostgreSQL, Redis, RabbitMQ, Prometheus,
  Grafana — только внутри сети Docker. Grafana — через SSH-туннель.
- Контейнеры приложения: файловая система только для чтения, `no-new-privileges`, без capabilities,
  процесс не от root.
- Зависимости: `pip-audit` в CI, Dependabot; образ — из фиксированного lock-файла.
